== 符号理論の「作法」を読み解く

本章では、LDPC符号のアルゴリズムをRTLへ落とし込む前に理解しておくべき、符号理論特有のルールや作法について解説します。
これらは通信理論の文脈で「暗黙知」として扱われることが多く、回路設計者が最初につまずきやすいポイントです。

=== 演算記号の正体： stem:[GF(2)] 上の演算

符号理論の論文に登場する stem:[+] や stem:[\cdot] の記号は、多くの場合、通常の数値計算（算術演算）ではありません。

* *stem:[GF(2)] 上の加算 (stem:[+])*
** 符号理論の基礎となるガロア体 stem:[GF(2)] における加算は、RTLにおける *XOR（排他的論理和）* と等価です。
** 例： stem:[1 + 1 = 0]
* *stem:[GF(2)] 上の乗算 (stem:[\cdot])*
** 乗算は *AND（論理積）* と等価です。
** 行列演算 stem:[H \mathbf{x} = \mathbf{0}] における内積計算などは、この AND と XOR の組み合わせで構成されます。

=== LLR (対数尤度比) の定義と採用理由

ハードウェア実装では、ビットが 0 または 1 である確率を直接扱わず、*LLR (Log-Likelihood Ratio)* を使用します。
本ドキュメントでは、基準文献である Chen (2005) に準拠し、以下の定義を採用します。

[stem]
++++
L(x) = \ln \left( \frac{P(x=0)}{P(x=1)} \right)
++++

==== LLR を採用するメリット
1. *演算の簡略化*: 確率の世界での「乗算」が、対数の世界では「加算」に置き換わります。
2. *ダイナミックレンジ*: 非常に小さな確率値を、固定小数点でも扱いやすい数値範囲にマッピングできます。
3. *判定の容易性*: 
* stem:[L(x) > 0] ならば、値は *0* である可能性が高い。
* stem:[L(x) < 0] ならば、値は *1* である可能性が高い。
* *MSB（符号ビット）* を確認するだけで硬判定が可能です。

=== メッセージの物理的意味

復号過程でやり取りされるメッセージ stem:[L(q_{n \to m})] や stem:[L(r_{m \to n})] は、RTL設計上は *「信頼度付きのデータバス」* と捉えることができます。

* *stem:[L(q_{n \to m})] (VN to CN)*: 
  変数ノードが周囲の情報を集計し、「自分はこれくらいの確信度で 0（または 1）だと思う」とチェックノードへ伝えるメッセージです。
* *stem:[L(r_{m \to n})] (CN to VN)*: 
  チェックノードがパリティ条件を照らし合わせ、「他の変数ノードの状況からすると、君は 0（または 1）であるべきだ」と変数ノードへ送り返す制約情報です。

[TIP]
====
この双方向のやり取りを繰り返すことで、全体のパリティ矛盾を解消していくのが LDPC 復号の本質です。
====
