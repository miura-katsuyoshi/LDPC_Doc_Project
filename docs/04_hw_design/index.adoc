== ハードウェア実装と ASIC 化の検討

本章では、Offset Min-Sum (OMS) アルゴリズムを具体的なデジタル回路として実装する際の、設計上の勘所とトレードオフについて解説します。

=== 1. 固定小数点化と量子化 (Quantization)

ASIC実装では、計算リソースとメモリ面積を削減するため、LLRを有限ビットの固定小数点数で表現します。

* *ビット幅の選定（設計例）*
** 一般的なLDPC復号器の設計例では、全ビット数 6ビット（整数部 4bit / 小数部 2bit）程度が採用されます。
** ただし、ATSC 3.0 のような高符号率・高次変調を扱う場合、性能要求に応じて 7～8 ビットへの拡張が必要になるケースがあります。最終的なビット幅は、BER シミュレーション結果に基づき決定する必要があります。
* *サチュレーション処理*
** 加算演算（VN更新）の結果が最大値・最小値を超えた場合、ラップアラウンド（符号反転）を防ぐために、必ず最大値/最小値に張り付かせる *クリッピング回路* が必要です。

=== 2. チェックノード演算の効率化：Min1 / Min2 探索

CN更新式における「自分自身を除く最小値」を個別に計算するのは非効率です。ハードウェアでは、全入力 stem:[\{ |L(q_{n' \to m})| \}] から、上位2つの最小値を探し出す手法が一般的です。

* *Min1*: 全体の第1最小値。
* *Min2*: 全体の第2最小値。
* *出力の選択ロジック（重複への注意）*
** 比較器ツリーでは *Min1の値* と共に、その *入力インデックス (Min1_idx)* も保持する必要があります。
** 入力ノード stem:[n] において、*自身のインデックス stem:[n] が Min1_idx と一致する場合* は *Min2* を採用し、それ以外の場合は *Min1* を採用します。
+
[CAUTION]
単に「値が Min1 と等しいか」だけで判定すると複数の入力が同じ最小値を持つ場合に誤って Min2を選択してしまい、復号性能が劣化する恐れがあります。

=== 3. 並列処理とレイヤード復号 (Layered Decoding)

ATSC 3.0 の QC-LDPC 符号は、パリティ検査行列が巡回置換行列（Sub-matrix）を単位として構成されています。

* *レイヤード復号のメリット*
** 全行列を一気に解くのではなく、行（レイヤ）ごとに逐次更新することで、収束速度（必要な反復回数）を SPA の約半分にまで短縮可能です。
* *メモリアクセスの設計方針*
** サブマトリクスの巡回シフト量に基づいたアドレス生成ロジックが必要です。
** ASIC実装においては、同一レイヤ内でのデータ依存性を排除し、パイプラインハザードが発生しないようにメモリバンク分割やスケジューリングを最適化することがスループット向上の鍵となります。

=== 4. オフセット項 stem:[\beta] のハードウェア定数化

stem:[\beta] は固定値として扱うのが一般的ですが、設計時に stem:[1/4] や stem:[1/2] といった stem:[2^k] の値に設定することで、減算器を単純なビットシフトと加算で代用し、さらに面積を削るテクニックもあります。
