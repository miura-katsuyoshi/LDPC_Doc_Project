# LDPC Decoder OMS Algorithm Document Project

LDPC デコーダ（Offset Min-Sum アルゴリズム）の理解と、新規参加者への技術継承を目的としたドキュメントプロジェクトです。

## 📖 プロジェクトの目的
*   **技術の明文化**: Offset Min-Sum (OMS) アルゴリズムの詳細とハードウェア実装への落とし込みを体系化する。
*   **教育資産の構築**: 符号理論の基礎知識がない回路設計者が、スムーズに設計・実装に参加できるようにする。
*   **ASIC実装への最適化**: RTL設計における量子化、並列度、スループット等の検討事項を整理する。

## 👥 推進体制
本プロジェクトは、人間とAIのハイブリッドチームで進めます。


| 役割 | 名前 | 担当内容 |
| :--- | :--- | :--- |
| **人間（承認者）** | **沖田** | 最終承認、プロジェクトの方向性決定、図解作成 |
| **AI（主案作成）** | **古代** | ドキュメントの執筆（第一稿の作成）、構成案の提示 |
| **AI（レビュー）** | **真田** | 技術的観点からのレビュー、実装上の課題指摘 |

## 🛠 ツールと形式
*   **ポータル**: README.md（Markdown形式）
*   **ドキュメント本体**: Asciidoc (`docs/*.adoc`)
*   **数式**: LaTeX 形式 (`stem` を使用)
*   **図表**:
    *   **draw.io**: `.drawio` ファイルを正本として管理。
    *   **画像形式**: `.svg` または `.png`（Git管理対象）。
    *   **その他**: PlantUML / Mermaid / Python (Matplotlib) も適宜使用。
*   **管理**: Git によるバージョン管理

## 📂 フォルダ構成
*   `docs/`: ドキュメントソース本体。`index.adoc` が親ファイル。
*   `figures/`: 図表、グラフ生成スクリプト
    *   `drawio/`: **draw.io ソースファイル（Git管理対象）**
    *   `images/`: **エクスポートされた画像ファイル（Git管理対象）**
    *   `scripts/`: ドキュメント掲載用のグラフ生成専用。
*   `references/`: 参考文献リスト。URLやBibTeX情報を管理。

## ⚙️ 環境構築
ドキュメントのビルド（HTML/PDF出力）には `Asciidoctor` が必要です。詳細は `docs/00_setup.adoc`（予定）を参照してください。

## 🚀 ワークフロー
1.  **沖田**が draw.io にて標準具体例（3×6行列）に基づく図解を作成。
2.  **古代**が各章のドラフト（主案）を執筆し、図解と整合させる。
3.  **真田**が技術的な妥当性と実装の観点からレビュー。
4.  **沖田**が内容を確認し、最終承認・マージを行う。
